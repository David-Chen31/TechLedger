# TechLedger MVP 架构与接口准备

状态：目标架构草案｜2026-10-28｜实际实现差异见下节；功能边界以 `PRD.md` 为准

## 当前实现与目标差异

本页其余章节记录的是目标设计，不能直接作为已实现功能清单。当前代码是 Next.js + FastAPI + PostgreSQL + 单 worker 的本地单用户原型：来源审核、固定快照引用、BM25/本地字符 n-gram TF-IDF/融合检索、确定性能力维度查询、单轮模型总结、决策卡生命周期和冻结检索评测可运行。尚未接入 Qdrant、语义 embedding、LangGraph 流程引擎、模型驱动多步工具循环、主题版本、完整预算控制和独立用户验证。`claims` 是程序核对过的原文摘录；模型摘要仍需人工复核。可验证的当前范围见[开发状态](remaining-work.md)与[冻结对照](research-retrieval-comparison-v0.1.md)。

## 1. 设计原则

1. 先保证可核查的来源与决策生命周期，再增加 Agent 自主性。
2. 每次运行绑定不可变来源快照、索引版本和流程配置；网页看到的结果与评测重放应指向相同材料。
3. 确定性的步骤（来源校验、引用存在性、状态转换）由程序负责；模型只处理问题拆解、证据归纳和取舍推断。
4. API 请求只创建或查询任务；较长的导入、索引和调研由有界 worker 执行。
5. MVP 是本地单用户应用，但数据模型为之后增加用户与权限保留明确边界，不伪称多租户安全。

## 2. 逻辑组件与数据流

```text
Next.js 网页 ── REST / SSE ── FastAPI API
                                  │
                         Application Service
                         ├─ Source Service ── Import/Parse/Index Worker
                         ├─ Research Service ── LangGraph Research Flow
                         ├─ Decision Service ── Review/Revision/Staleness
                         └─ Evaluation Service ── Frozen Cases/Replay/Report
                                  │
               PostgreSQL（元数据、事件、决策、关键词索引）
               Qdrant（向量检索；仅已批准可索引快照）
               受限来源连接器（白名单公开 URL）
               Model Provider（真实/模拟）
```

发布内容的原始快照是否本地保存，取决于来源许可；可保存时使用受控文件目录或对象存储，不为了使用 MinIO 而增加服务。来源连接器、解析器、检索器和模型 Provider 各自通过明确接口接入，便于离线测试。

## 3. 核心实体

| 实体 | 必要字段与关系 | 不变量 |
|---|---|---|
| Topic | ID、名称、范围、允许来源列表、对比维度、版本 | 一次评测绑定一个 Topic 版本 |
| Source | ID、规范 URL、所有者、类型、许可判断、状态 | URL 必须来自白名单；禁用来源不再被新运行召回 |
| SourceSnapshot | ID、Source ID、抓取时间、声明版本/日期、内容哈希、保存策略、解析状态 | 快照不可原地覆盖 |
| Chunk | ID、Snapshot ID、章节路径、文本范围/哈希、索引版本 | 引用必须回到有效快照与范围 |
| IndexVersion | ID、解析规则版本、检索配置、embedding 模型标识、完成状态 | 索引未完成不得成为默认检索版本 |
| ResearchRun | ID、问题、硬约束、候选方案、来源快照集合、索引版本、流程/模型配置、状态、预算、停止原因 | 运行创建后输入和绑定版本不变 |
| RunEvent | Run ID、任务内递增序号、阶段、事件类型、时间、可见摘要、证据引用 | 同一运行事件顺序稳定；不得暴露密钥或原始隐私数据 |
| Evidence/Claim | 主张、候选方案、支持/反驳关系、引用快照/片段、核验状态 | 无有效引用的外部事实不得成为“已证实” |
| DecisionCard/Revision | Run ID、问题、比较矩阵、建议、未知项、草稿/批准/退回/废弃状态、修订号 | 已批准修订不可覆写；修改生成新修订 |
| ReviewAction | Card/Revision ID、动作、时间、修改内容、理由 | 只有批准动作使卡片进入知识检索范围 |
| EvalCase/EvalRun | 冻结输入、核查点、数据版本、执行配置、逐例评分 | 正式评测用例不在跑分过程中静默修改 |

数据库迁移需跟随实体变化；向量库只保存可重建索引，PostgreSQL 中的来源快照/Chunk 元数据是权威记录。删除或禁用来源时记录操作结果，并检查两处索引一致性。

## 4. 生命周期与状态

**来源导入**：`registered → fetching → parsed → indexing → ready`；失败进入 `fetch_failed`、`parse_failed` 或 `index_failed`，各状态均可重试并保留原因。新快照索引成功前，旧可用快照仍保持可查询，网页明确显示其时间。

**调研运行**：`created → queued → running → completed | partial | failed | cancelled`。`completed` 只表示流程结束，不代表结论已获批准。服务重启后未完成任务转为 `interrupted`，由人工或恢复策略决定重试，不直接显示成功。

**决策卡**：`draft → approved | returned`；已批准修订在来源变化后进入 `needs_review`，用户处理后成为新的 `reconfirmed` 或 `revised` 修订，也可 `retired`。来源变化只触发复核状态，不能自动宣告原决策错误。

## 5. 调研流程与上下文策略

1. **Input validation**：提取问题、硬约束、候选方案；缺少决策所需关键约束时返回澄清提示。
2. **Plan**：生成有限的比较维度与需要核查的事实；计划可见，不能添加白名单外来源。
3. **Retrieve**：关键词与向量结果合并、去重，按来源与版本过滤；逐维度选择有限片段。
4. **Extract**：形成原子化主张与所依赖证据，标明事实、推断或未知。
5. **Verify**：程序检查快照、片段、版本与引用存在性；模型可指出冲突、再检索缺失维度，最多有限轮次。
6. **Synthesize**：生成比较矩阵、建议、约束匹配理由和剩余风险。
7. **Review**：模型产物仅为草稿；用户修改或批准后进入决策库。

短期状态保存问题、计划、已查来源、关键证据、未解决冲突、步骤数与预算。避免将全部原文塞入每次模型调用：保留用户硬约束和当前高相关片段，压缩中间过程但不丢原始事件。模型输出必须经过结构和引用校验。每个节点有独立超时、错误类别与可观察事件。

## 6. REST 与事件契约（设计稿）

| 资源/动作 | 预期能力 | 关键约束 |
|---|---|---|
| Topics | 列表、读取预置主题及版本 | MVP 不支持任意用户建主题 |
| Sources | 登记、列表、同步、查看快照与错误、禁用/删除 | 登记必须通过白名单与许可检查 |
| Research runs | 创建、读取状态/结果、取消、读取事件 | 创建返回运行 ID；重复提交可用幂等键避免重复运行 |
| Decision cards | 读取草稿、批准、修改、退回、查看修订、标记废弃 | 已批准版本不可原地覆盖 |
| Evaluations | 查看冻结用例集、启动对照、读取逐例结果与汇总 | 正式结果绑定数据与配置版本 |

SSE 每条事件包含运行 ID、递增事件 ID、时间、阶段、事件类型与不含密钥的摘要；断线重连依据 `Last-Event-ID` 补发数据库中已持久化事件。事件先落盘再推送，网页刷新后仍能查询相同状态。需要人工操作的动作使用明确 REST 请求，不通过 SSE 反向提交。

错误响应包括稳定的错误码、用户可读说明和可重试性；至少区分输入不完整、来源未批准、来源不可用、解析失败、索引失败、模型限流/超时、预算耗尽、引用校验失败、运行已取消。

## 7. 安全、失败恢复与可观测性

- 来源连接器只访问人工批准的域名与路径；限制重定向、下载大小、内容类型和超时，避免内网访问与无限抓取。
- 模型密钥仅由服务端读取；网页、事件、错误和导出的评测数据不得包含密钥。外部资料不得修改工具权限或系统提示。
- 模型与来源访问设置独立超时和有限重试；预算耗尽时停止并保留部分证据。取消需停止后续模型调用与索引提交。
- 记录各阶段耗时、召回片段数、引用校验失败、Token、费用估计、错误类型和重试次数。指标报告包含失败任务，不只统计成功任务。
- 用模拟 Provider 和固定来源快照做 CI；真实来源同步与付费模型调用作为单独的可控演示步骤。

## 8. 主要架构取舍

| 选择 | 理由 | 何时重新评估 |
|---|---|---|
| 受限单领域流程，而非任意节点画布 | 保证 4–8 周内有可信产品闭环 | 用户确需调整流程结构且能评测收益时 |
| 来源快照不可变 | 支持引用核查和重放 | 无需取消；仅调整保留策略 |
| PostgreSQL 为权威数据，Qdrant 为可重建索引 | 避免元数据和向量状态互相争夺事实来源 | 数据规模或部署条件变化时 |
| 关键词基线先行，向量检索作为可测增量 | 确认额外依赖确实提高质量 | 固定评测集完成后 |
| 单 worker 有界执行 | 本地单用户演示足够，故障更易诊断 | 并发任务需求有证据时 |
| 人工批准后才进入知识库 | 防止未经核查的模型输出污染后续检索 | 审查准确率与风险被量化后 |
