# TechLedger 来源、证据与知识生命周期规范

状态：开发前草案｜2026-10-28

## 1. 信任边界

来源页面、用户问题和模型输出均是不可信输入。只有项目配置中的来源白名单、工具权限和数据结构校验能决定系统行为。网页中的“忽略上述规则”等文本不得成为流程指令。系统不执行来源中的代码、命令或脚本。

首版仅导入人工登记的公开来源，不开放任意 URL 抓取。每个来源须先确认所有者、用途、可访问方式和引用/保存限制；不能因为“公开可读”就推定可以再发布全文。面向用户只展示必要短片段、标题和原始链接。若来源条款不允许保存或展示内容，应仅保存允许的元数据并改用链接核查，或从 MVP 来源清单移除。

## 2. 来源类型与登记字段

| 类型 | 例子 | 必需元数据 | 初始处理 |
|---|---|---|---|
| 官方文档 | 项目概念、安装、能力说明 | 规范 URL、标题、所属产品、抓取时间、文档声明版本、内容哈希、许可状态 | 结构化切片、引用到章节 |
| 官方发布记录 | GitHub Releases 或官方 changelog | 版本号、发布日期、规范 URL、抓取时间、内容哈希 | 按版本与变更项切片 |
| 用户确认的团队决策 | 已批准的技术决策卡 | 决策版本、批准时间、关联来源快照、复核状态 | 与外部事实分开索引，不能自动替代原始证据 |

候选演示来源见 `docs/01-product-brief.md`。登记来源时记录“允许抓取、允许本地索引、允许展示短引用、允许发布评测数据”四个独立判断；未知视为未批准。发布评测时优先公开问题、URL、版本、标注和指标，原文片段按各来源许可处理。

## 3. 快照与切片规则

1. `Source` 表示一个规范来源入口；`Snapshot` 表示某时刻获取的不可变内容。新同步不能覆盖旧快照。
2. 同一 URL 的内容哈希不变时只记录同步事件，不重复索引。若哈希变化，生成新快照并记录旧、新快照关系。
3. 保留页面标题层级、章节锚点、发布日期或声明版本。时间缺失时标记 `unknown`，不能由抓取时间冒充发布日期。
4. 文档按标题/段落切片；发布记录按版本和变更项切片。每片保留来源 ID、快照 ID、章节路径、文本范围、内容哈希和检索可用状态。
5. 去除导航、模板页脚与明显重复片段；保留清洗前后哈希和解析错误。切片规则或 embedding 模型变化时生成新的索引版本。
6. 删除来源时同步删除可检索切片与向量索引；历史决策引用的快照按保留策略处理，至少保留可核查的来源元数据和 URL，不能留下可检索的孤儿向量。

## 4. 主张与引用契约

每个进入决策卡的关键事实应保存：主张原文、主张类型（能力/限制/版本/许可/成本/其他）、对应候选方案、来源快照 ID、章节或锚点、支持片段、证据关系（支持/反驳/背景）、核验状态和核验时间。

**引用有效**表示：来源入口可定位，片段确实存在于绑定快照，并且片段语义支持该主张。程序校验负责 URL/快照/范围存在性；语义支持需要人工标注或审查。来自不同时间的互相矛盾材料应展示其版本和日期，不能合并成一句无版本的结论。

决策卡至少区分四种语气：已由来源支持、存在相反证据、尚未找到证据、基于约束的推断。推断必须显式写出依据与假设，不能伪装为官方事实。用户修改后的文字要重新检查引用关系。

## 5. 新鲜度与失效状态

**变化检测**只回答“绑定来源与上次不同”；**结论失效**需要复核，二者不能等同。

状态：`current`（来源未变或已复核）→ `needs_review`（引用来源变化）→ 用户选择 `reconfirmed`、`revised` 或 `retired`。每次操作记录操作者、时间、旧/新来源、受影响主张和理由。新旧快照均需能查看；若因许可只能保留元数据，则展示 URL、版本与变更摘要，并说明无法本地复原全文。

MVP 通过手动重新同步触发变化检测。自动定时同步、提醒通知和自动判断“变化是否推翻结论”留到后续。来源无版本/日期时，决策卡必须显示“时效未知”。

## 6. 检索策略与污染控制

- 先用关键词检索建立可解释的基线；再加向量检索，并在固定题集上判断其增益。两者输出统一的 `Evidence` 结构。
- 仅从登记且当前允许索引的来源中召回。用户硬约束和正式来源内容分开存储，不让文档文本覆盖用户约束。
- 限制上下文 Token，按问题维度选择高信号片段；同一来源的近重复片段合并，避免数量多的一方压倒另一方。
- 每条生成主张都要经过引用存在性校验。无法校验的主张退回为待核查或从最终卡片移除。
- 团队已批准决策可以帮助发现历史上下文，但不能作为外部产品能力的唯一依据；此类事实仍要回溯官方来源。

## 7. 开发前必须完成的来源审查

为每个候选来源填写：规范 URL、所有者、页面类型、版本/日期字段可用性、允许的数据处理方式、解析可行性、抓取频率、失败替代方案。至少准备一份版本变化案例和一份来源冲突案例。任何来源审查不通过时，替换来源并重新冻结评测数据，不临时绕开限制。
